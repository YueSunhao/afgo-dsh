# afgo-dsh UX v3 设计规范

**范围**：插件工作台、对话工具卡片、结果可视化、任务流程与时间线。
**原型**：[`ux-v3-mock.html`](ux-v3-mock.html)，可直接用浏览器打开；在地址后加 `?theme=light` 切换到浅色。
**截图**：[`ux-v3/mock-dark-1280.png`](ux-v3/mock-dark-1280.png)、[`ux-v3/mock-light-1280.png`](ux-v3/mock-light-1280.png)、[`ux-v3/mock-dark-760.png`](ux-v3/mock-dark-760.png)。

原型用的是假数据，只用于评审视觉、排版和信息层级，不代表真实计算结果。原型里深色主题的颜色是根据截图估出来的；真实插件不定义这些颜色，只读取宿主的 `--dsw-alias-*` 变量。

---

## 1. 设计原则

1. **结论优先，细节可展开。** 打开任务后，第一屏要能回答三件事：任务成功了吗、关键数值是多少、结构长什么样。原始 key-value、文件 ID、sha256、调度器时间都收进折叠区或 `ⓘ` 提示。这样实验背景的用户能直接拿到结论，计算背景的用户想核对时，点一次就能看到依据。
2. **融入 DSH。** 颜色只用宿主变量，不加品牌色，不加载外部字体。深浅色主题完全跟随宿主；查看器 iframe 和图表也一样跟随。
3. **不推断，不估算。** 继续遵守 v2 的规则：
   - 执行状态、结果判定、同步状态是三个独立信号；
   - 只画平台返回的时间；
   - 进度条按「已完成步骤数 / 总步骤数」计算，不是时间估算；
   - 高亮的值只表示「最小值」或「最大值」，不写成「最优」；
   - 键线是推断出来的，要明确标出。
4. **一个页面只有一个滚动条。** 列表列吸顶，详情列跟随页面滚动，不出现嵌套滚动。
5. **说明文字少而准。** 常驻的说明小字改成 `ⓘ` 悬停提示。正文只保留会影响用户判断的那一句。

## 2. 设计令牌

令牌定义在 `.afgo2` 根元素上。后面实现时会把它们原样移到 `lib/client.js` 的 `styles` 顶部，现有的写死数值全部替换成令牌。

| 类别 | 令牌 | 取值 |
|---|---|---|
| 间距 | `--afgo-s1…s6` | 4 / 8 / 12 / 16 / 24 / 32 px |
| 圆角 | `--afgo-r-s/m/l` | 6 / 8 / 12 px（胶囊形状用 999px） |
| 字号 | `--afgo-fs-xs/s/m/l/xl/xxl` | 12 / 13 / 14 / 16 / 20 / 28 px |
| 文字色 | `--afgo-fg`、`-2`、`-3`、`-4` | `label-primary` / `secondary` / `tertiary` / `caption` |
| 面 | `--afgo-bg`、`--afgo-layer-1`、`--afgo-layer-2` | `bg-base` / `bg-layer-1` / `bg-layer-2` |
| 线 | `--afgo-line-1`、`-2`、`-3` | `border-l1` / `l2` / `l3` |
| 强调 | `--afgo-accent` | `link` |
| 状态 | `--afgo-ok`、`warn`、`err` 及各自的 `*-soft` | `state-success/warn/error-primary` 与 `tertiary` |
| 图表 | `--afgo-chart-1`、`--afgo-chart-muted` | `accent` / `line-3` |

**用法规则**

- 数字一律使用 `font-variant-numeric: tabular-nums`。
- 等宽字体只用在编号、文件名和哈希上。
- 每个令牌都带一个浅色 hex 回退值，宿主没提供变量时也能显示。不再写 `--dsw-alias-text-primary` 这类不存在的变量名。

## 3. 组件

| 组件 | 说明 | 原型位置 |
|---|---|---|
| 按钮 | 四种 `data-variant`：`primary`、默认（次要）、`text`、`icon`。高度 32px，紧凑场景 28px | 各画板 |
| 状态点 `.afgo2-dot` | `data-tone`：`ok`、`warn`、`err`、`run`（脉冲）、`unread`（空心）。列表行只用状态点，不用文字徽标 | 画板 1 列表 |
| 状态徽标 `.afgo2-chip` | 和状态点使用相同的 tone。只用在判定和步骤状态上 | 画板 1、3 |
| 信号行 | 执行 · 判定 · 同步三项横向排列，每项都有标签。判定依据放在 `ⓘ` 里 | 画板 1 标题下方 |
| 指标卡 `.afgo2-metric` | 标签带 `ⓘ`（来源列和原始值），数值保留 4–6 位有效数字，单位单独用小字显示，最后一行是上下文 | 画板 1、2、4 |
| 分段选择 `.afgo2-seg` | 用来切换结果文件，代替下拉框，后面带类型小字（结构 / 图 / 表） | 画板 1 |
| 查看器外框 | 工具栏只占一行；底部注释行显示原子数、晶胞、「键线为推断」（警告色） | 画板 1 |
| 折叠区 `.afgo2-disclosure` | 「来源与校验」「调度器时间」都用它，默认收起 | 画板 3、4 |
| `ⓘ` 提示 `.afgo2-hint` | 悬停或获得焦点时显示，宽 240px | 多处 |
| 骨架屏 | 按最终布局的形状显示占位，取代纯文字的「正在读取…」 | 画板 5 |
| 空状态 / 提示条 | 主文案写结论，次要文案写原因或下一步；错误附带 `request_id` | 画板 5 |

## 4. 页面

### 4.1 工作台顶栏（画板 1）

- 一行布局：品牌名 · 账号胶囊（状态点、账号、环境、同步时间，点击进入「设置」）· 右侧是「# 任务编号 [打开]」输入框。
- 去掉「继续查看 #id」「发现工具」「输入任务编号」「账号设置」四个按钮，因为它们和标签页重复。
- 「上次查看的任务」改为打开页面时自动选中。
- 一级标签：我的任务 / 发现工具 / 设置。

### 4.2 任务列表

- 按日期分组（今天 / 更早）。
- 每行两行内容：
  - 第一行是标题，只占一行，超长截断。标题由工具简称和关键输入组成；拿不到时回退到原描述。
  - 第二行是 `#id · 状态词 · 时间 · 耗时`。
- 状态点：
  - 从未打开的任务用空心点，悬停显示「未打开，状态未读取」；
  - 运行中用蓝色脉冲点；
  - 其他状态取缓存的判定结果。
- plan_id 用同样的行样式，次行标注「工作流」。

### 4.3 任务详情：结论优先

1. **标题区**：小字一行写 `#id · 工具 · 版本 · 任务类型`，下面是 20px 标题，再下面是信号行。
2. **结果摘要卡**：左边放主指标、2–3 个次要指标和操作按钮（下载主结果 / 全部文件），右边放代表结构或代表图的缩略图。主指标按这个顺序取：
   1. 主结果文件按 `PRIMARY_RULES` 指定的列；
   2. 没有规则时，取首个数值列，配同一行的标签列；
   3. 都没有时，只显示判定结果和文件数量。
3. **子标签**：
   - **结果**（默认打开）：可视化 + 数值图表；
   - **过程**：时间线、事件、工作流节点；
   - **文件**：产物列表和预览；
   - **详情**：原始 key-value、证据、最后一条可读回复。
4. **结果标签页**：先用分段选择切换文件，下面是查看器或图表。

### 4.4 数值结果（画板 2）

| 数据量 | 展示 | 说明 |
|---|---|---|
| 1 个值 | 指标卡 | 不画图 |
| 2–30 个值 | 水平条形图，按数值排序 | 有标签列时用标签，否则用「行 n」。只高亮最小值，并注明「只说明它是最小值」 |
| 30 个以上 | 折线图 + 图/表切换 | 横轴是原始行序或步数；末点标出数值 |

**列名解析**（`columnLabelOf`）：

- 先尝试解析出量的名称和单位，例如 `Gamma_J_per_m2` → 表面能 γ（J/m²），`*_eV` → eV，`*_A` / `rmsd_A` → Å，`*_kcal_mol` → kcal/mol。
- 解析不出来时保留原列名。
- 原始列名始终在 `ⓘ` 里可以看到。

**数值格式**（`formatValue`）：

- 默认保留 5 位有效数字；绝对值大于 1000 时保留 1–3 位小数。
- 原始值放进 title，并可以复制。

### 4.5 结构查看器

- 尺寸：宽高比 4:3，最小 360px，最大 620px，另有全屏按钮。
- 工具栏左侧：表示方式、聚焦、重置视野；右侧：全屏、⋯（导出 PNG、来源记录、关于查看器）。
- 画布背景用 `--afgo-bg`。查看器颜色由宿主读取计算后的变量，再通过 postMessage 传进 iframe。
- 无头渲染的对话图固定用浅色背景，保证图片稳定。
- 帧滑块：用 requestAnimationFrame 节流，复用场景只更新坐标；外加心跳检测，超时后提示「视图无响应，已停止」。

### 4.6 过程（画板 3）

- **步骤数 ≤ 3**：纵向步进条。每步显示名称、状态徽标、开始和结束时间、排队时长，以及一条细的「排队（虚线）+ 运行」比例条，右侧是耗时。运行中的步骤显示「已运行 X」。
- **步骤数 > 3**：保留 v2 的比例时间轴，图例和步进条统一。
- **调度器时间**：放在折叠区里单独列出，不和步骤时间混在一起。
- **工作流**：节点卡片从左到右排，用箭头连接，每个节点显示状态点、状态和关联任务链接。接口降级时显示警告徽标，`ⓘ` 里说明原因。DAG 布局放到后续版本。

### 4.7 对话工具卡片（画板 4）

- **完成**
  - 标题行：工具名 · `#id` · 判定徽标 · 完成时间。
  - 最多 3 个指标。
  - 两张大图（代表结构和结果图）交给宿主图库展示，下面是文件名说明。
  - 「来源与校验」默认收起，里面是短 ID、sha256 前 8 位和复制按钮。
- **运行中**：步骤 n/m、当前步骤名、按步骤数计算的进度条、已运行时长、刷新时间。不显示图片。
- **失败**：错误提示条写清失败的步骤和原因，附 `request_id`；下方是「查看日志」和「复制错误」。
- **`report.markdown`**：正文只嵌入图片和一个「来源记录」链接，不再写文件 ID 和 sha256。`instruction` 里同时要求模型不要复述这些值。

### 4.8 加载、空状态与错误（画板 5）

- 加载时用骨架屏。
- 空状态写清「没有什么」和「去哪里找」。
- 同步延迟用警告色提示条，并给出下次自动重试的时间。
- 403、404 和网络错误分别写出人能看懂的原因，附 `request_id`。

## 5. 窄屏（宽度 < 860px）

- 列表和详情切换显示，详情顶部有「← 任务列表」。
- 结果摘要卡改成上下排列，缩略图高 180px。
- 两列和三列布局都改成一列。
- 对话卡片里的两张图改为上下排列。
- 原型在窄屏下发现一个问题：折线图的 SVG 整体缩小后，字号太小。实现时改成按容器宽度计算 viewBox，或者窄屏下减少刻度数。

## 6. 文案调整

| 位置 | 现在 | 改为 |
|---|---|---|
| 页脚 | 本页只读取平台数据… | 本页只读取平台数据；提交示例任务需要你在页面上确认 |
| 列表状态 | 待查询（文字徽标） | 空心状态点，悬停显示「未打开，状态未读取」 |
| 数值说明 | 单位与科学含义以原列名及报告为准 | 放进 `ⓘ`，正文不写 |
| 高亮 | （无） | 只说明它是最小值，不代表最优 |
| 查看器 | Mol* 5.13.1（显示在工具栏） | 移到 ⋯ →「关于查看器」 |
| 设置 | 调度器时间优先 | 步骤时间来自平台的步骤记录；调度器时间单独列出 |

## 7. 实现顺序

和计划一致，每个阶段一个 PR：

- **A**：令牌和通用组件、修复主题断点、数值格式化工具函数、修复导出文件名。
- **B**：工作台信息架构，包括顶栏、列表、结论优先的详情页。
- **C**：可视化，包括统一候选排序和判定、查看器尺寸和帧切换、新的数值图表。
- **D**：对话卡片和精简后的 `report.markdown`。
- **E**：时间线步进条、调度器时间、工作流只读视图。
